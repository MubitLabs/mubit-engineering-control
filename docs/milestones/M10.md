# M10 — Pilot hardening

**Backlog tickets:** 22 (crash and partition reconciliation), 23 (backups and restore drill —
metrics later), 24 (pilot deployment and runbook).

## What it does

- **Restore without duplicate work.** If control is restored from an older backup, its record of
  each attempt is behind the runners'. Runners now *rewind*: when control acknowledges an older
  sequence than they hold, they reload the missing events from their journal and replay them, so the
  restored database converges with no gaps or duplicates. An attempt the restored database has never
  heard of is stopped on the runner (workspace kept) and reported as `runner.unknown_attempt`, so the
  same task cannot run twice once dispatch resumes.
- **Restore drill.** `deploy/restore-drill.sh` restores the newest backup into a scratch database on
  the droplet and checks invariants (migrations, one active attempt per task, gap-free event
  streams, stream counters, no double resolution). It passes against the production backup.
- **Runbook** (`docs/RUNBOOK.md`): what runs where, deploy and rollback, one-time setup, launch
  checks, stalled-work triage by blocker, draining a runner, fleet stop, restore, rotating
  credentials.

## Pilot

The v1 acceptance run — a real plan on `MubitLabs/mec-sandbox` through coordinator → approval →
two parallel Claude Code attempts → a decision answered in the inbox → an interrupted attempt
resumed → review → integration checks on the exact SHA → PR — needs the one-time setup in the
runbook (GitHub OAuth app, Claude Code sign-in on the droplet, the sandbox repository and its token).
Every step has been exercised with the fake agent and a stand-in Claude CLI in the tests, and the
full plan → review → integration loop was run in a browser against a local control plane.
