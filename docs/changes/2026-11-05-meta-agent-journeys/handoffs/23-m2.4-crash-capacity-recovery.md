## Outcome

Kill the server at any boundary and restart: one authoritative effect, no orphan process, the same worktree, no duplicate work. Pause, hold and stop behave as the spec says across restarts. A quota or auth hit parks work and resumes it, or an owner-approved switch moves it. Codex and OpenCode launch through the same runner, each advertised only after its own proof.

## Requirements: Part A

1. **Boot order (§20, O9).** Lock → journal replay → process reconciliation → external reconciliation → then effects resume and passes start. Today `reconcileRunningAttempts` only flips `running` to `stalled` and starts nothing. `11` adds boot resume of receipt-less messages after it; keep that after replay too. A resumed `launch` row must be safe: 20's handler returns if the attempt isn't `queued`.
2. **Journal replay (§8.6, §26).** Implement `Runtime.replay`: `journal.pending()` → facts → ack after commit. Dedupe by attempt, generation and seq, so a crash after commit and before ack applies nothing twice.
3. **No orphans.** Attempts run in detached groups that outlive the server, and `Supervisor.owned` is memory only. Persist pid and start time on the attempt doc at launch. At boot, confirm identity (start time from `ps`, not the pid alone: pids are reused), then SIGTERM → SIGKILL → confirmed gone (§8.1). A process that isn't provably ours is never signalled and is reported instead.
4. **Restart (§20).** Running attempts end as "host restarted" and start again with a recovery note (`Input` kind `recovery`), oldest work item first, on the same worktree. Those waiting, ready, blocked or failed stay unless an input reached them. Transitions: `stalled → reconciled_stopped → interrupted → resume`. New generation, new token. `#replay` hardcodes `generation: 1` (`service.ts:929`). Same-slot session resume only.
5. **External reconciliation (§17, §20).** On `fix/release-cards`, `resolvePush` and friends settle the card, then call git or gh inside the HTTP request, not through the `external` effect. A crash between leaves an `approved` card with no outcome event. At boot, find those and read the remote: `ls-remote` for a push, PR by head for a create, PR state for a merge. Record the observed outcome. Absent means not sent, and a retry is a new card (`resolvePush` doc). Never repeat from an approval alone.
6. **Pause (#21, §20, §26).** `10` delivers persistence, the shift and the routes. This PR adds what attempts need. Pause stops launches, deliveries, relays and outbound messages; running turns continue, and their reports and checks still record. The timer's `if (paused) return` (`composition.ts:114`) stops every kind, including `probe`, and would strand a finishing attempt's work: make it per kind with `Later`. The UI control (#22) is `32-m3.3-setup-configuration.md`.
7. **Stop (§12.5, §13.4).** `interrupted` only after the group is confirmed gone. A failed stop stays visible. Stop during planning, launch or checks launches nothing later.
8. **Hold on running work (§12.5).** See the open question. No new launch or delivery either way.
9. **Live parking (§5.10).** Today `parkFromEvents` runs at exit. Park as events arrive: `rate_limit` rejected, error classes. Release capacity, keep worktree, degrade the slot, write the same facts to chat and the meta agent. Unattended parks wake per `classifyWake`.
10. **`probe` effect (§5.8, §17).** It's a no-op at base (`composition.ts:343`), and `11` makes it throw `unsupported effect`. Wire it with `@mec/slots` probes on a timer. This also closes a gap: no server path turns a `claude-sub` slot `healthy`. Only API-key validate does (`server.ts:904`), and `mec slot` hardcodes `~/.mec`. Feed utilisation into placement, with the 80% ceiling (§11).
11. **Resume (§5.10).** Reported reset plus healthy probe, or next healthy probe when unknown, or an explicit action. Revalidate the mandate first (§10). Never lift a hold.
12. **Switch (§5.10, §13).** `POST /api/work/:id/switch-slot` behind a `slot_switch` confirmation unless pre-authorised. Use `planFailover`. Re-probe the target. Record a handoff doc: from, to, reason, time, pack. New attempt, same worktree, never a resumed session across slots or engines. Auth parks never switch. Auto pairs come only from policy.
13. **Shutdown and CLI (§20, O9).** `11` bounds `close` and closes the brain. Add the 10s per attempt stop for background work (§20). `mec restart` injects `startServer: async () => {}` and prints "server starting" (`mec.ts:190`): make it real or say it doesn't restart. `cliMain` ignores `MEC_DATA_DIR`.
14. **Sleep and stall (§20).** A silent journal plus a dead group gives `stall_detected`; re-arm timers on wake. Replacement starts only after reconciliation.
15. **Records.** Update `docs/fault-suite.md` rows for restart, failover, hold, pause, and auth expiry. Add real evidence to `HANDSHAKES.md`. Keep dated credit.

## Requirements: Part B

Pins: `docs/engines.md` (codex-cli 0.148.0, opencode 2.2.5). Spec §9's versions differ; don't upgrade. Do each engine as its own commit and proof.

1. **Codex client.** The adapter expects an injected client, and the only one is inside `codex.real.test.ts` (`startAppServer`). Extract it to `packages/runtime/src/codex-client.ts`, using `buildAgentEnv`, `slot.env` and owned spawn.
2. **OpenCode client.** Same for `opencode serve --stdio` per §9 and the launch recipe in `docs/engines.md`. Keys come only via `SlotKeystore.read()` at launch. Keep the permission reply inside the read loop (`opencode/adapter.ts` Launch note).
3. **Tool access per attempt.** Source gap, not run: `thread/start` sends only `cwd, sandbox, approvalPolicy, model`, and OpenCode's session POST carries no MCP config. §6 puts these in slot config, but the token is per attempt. §9 lists a `config` field on `thread/start`; unproven here. See the open question.
4. **`launch` re-initialises.** `CodexAdapter.launch` sends `initialize` on every call. On one shared process a second attempt may be refused. Unverified: test with a fake first.
5. **Bridge.** Both engines reuse 20's decider through `spec.bridge`. A native request maps to exactly one decision. An expiry denies. Same always-confirm rules.
6. **Isolation (§8.4).** Codex `workspace-write` and never trusted. OpenCode has no OS sandbox: slot `permissions`, `OPENCODE_DISABLE_PROJECT_CONFIG=1`.
7. **Reports and checks.** Same runner path: journal, facts, head, checks. `mapReport` and `classify` fixtures stay honest.
8. **Registry.** Add a row only when its proof passes. `Capabilities` state what was proven (§9). `send` is advertised only if proven, which needs 21's `deliver`; otherwise it stays unsupported with an explicit failure.
9. **Probe.** `probe` per engine on launch for drift, degrading to `engine_unsupported` (§26).

## Open questions

1. **§9, §6, §8.1: one engine server per slot, or per attempt?** §9 says per slot. Per-attempt token, `MEC_*`, shim `PATH` and §5.12's attempt layer can't reach a shared process. §8.1 accepts this for OpenCode's sessions; §9's table is less explicit for Codex. Recommend one server per attempt for this release: true env isolation and simple stop, at higher startup cost. If per-slot must hold, deliver tokens through `thread/start` `config` and accept a shared env, with a spec line.
2. **§12.5: does a hold interrupt a running attempt?** §10 and §12.5 say a hold persists and blocks; neither says the running turn stops. #20 covers plans. Recommend it keeps running to its turn end, with no new input, and §20's "running turns are not interrupted" as the model.
3. **§20: a running attempt at restart, killed or kept?** "End as host restarted" implies killed. Recommend killing and restarting with a recovery note, never adopting: its stdout pipe is gone.
4. **§17 vs `fix/release-cards`: should external effects go through the `external` queue?** They run inline in the request. Recommend keeping that and reconciling at boot, since cards are already compare-and-set. Moving them is a larger change with no requirement behind it.
5. **§5.10: unknown reset with no healthy probe path.** A slot with no probe can't resume. Recommend explicit action only.
