# M5 — Scheduler, leases and recovery

**Backlog tickets:** 16 (scheduler, fair limits, leases, outbox dispatch), 21 (quota and auth
waits, explicit reassignment — partial), 22 (crash and partition reconciliation — partial).

## What it does

- **Deterministic scheduler.** Every second (and immediately after any event) control plans
  dispatches with the pure `planDispatches` from `@mec/domain`: delivery priority first, then a fair
  rotation across projects (the n-th oldest task of each project before the (n+1)-th of any), then
  age. Limits: global (2 on the droplet, 6 by default), per employee (runner owner), per delivery,
  per execution profile, per runner capacity. Tasks that cannot start record why as a `capacity` or
  `infrastructure` blocker.
- **Atomic claim, re-checked.** Each dispatch is claimed in its own transaction under a global
  dispatch advisory lock, where the limits, project pause and fleet stop are checked again against
  the live database. Manual starts go through exactly the same claim.
- **Lease expiry → reconciliation, not replacement.** A lease that is not renewed by heartbeats
  moves the attempt to `stalled`: it keeps its slot and its task waits with an `infrastructure`
  blocker. When the runner reconnects and reports the attempt with the same generation, it is
  un-stalled and its journal replays whatever happened meanwhile. If the machine is gone, an
  operator confirms the stop; only then can the work be resumed or abandoned. The single exception
  is an attempt whose start command never reached the runner: it is released back to the queue and
  the command withdrawn.
- **Generation fencing.** Resume bumps the generation and sends `resume` to the attempt's own
  runner (its workspace lives there). Anything from the older generation is stored as evidence but
  never changes state.
- **Pausing.** A project pause stops new dispatch for that project. A fleet stop pauses all
  dispatch, sends an interrupt to every live attempt and tracks each acknowledgement; a disconnected
  runner shows as unreachable rather than stopped. Resume dispatch from the Fleet page.
- **Control restart.** Unacknowledged commands are resent as soon as a runner reconnects; leases are
  not expired during a short startup grace period so runners can reconnect first.

## How to demo

The fault suite (`pnpm vitest run apps/control/test/scheduler.test.ts`) runs with the real runner
and fake agent or the scripted fake runner:

- three ready tasks with a global limit of 2: never more than 2 active, the third waits with a
  visible reason and starts when a slot frees;
- five concurrent dispatches of one task produce one attempt;
- a silent runner's attempt becomes `stalled`, then `running` again when the runner returns;
- an undelivered start is released, and the runner never receives it later;
- after a resume, generation-1 events are fenced;
- a second connection for the same runner closes the first (`4000`);
- control is stopped and restarted mid-attempt: the attempt completes, one attempt exists, and
  event sequences are contiguous;
- an interrupted attempt resumes from its checkpoint without repeating steps;
- a fleet stop interrupts both attempts, every runner acknowledges, and nothing new starts until
  dispatch is resumed.
