# M3.4: Accessibility and local release

Read `00-README.md` first. This handoff is four PRs, in order. Stage A can start as soon as VF0 and `fix/release-cards` merge. The rest wait for everything else.

**Branch:** Stage A `feat/a11y-runner`. Stage B `feat/next-default`. Stage C `chore/remove-classic-shell`. Stage D `chore/version-<version>`, once per release.
**Size:** Stage A S. Stage B L. Stage C M. Stage D S.
**Model:** Stage A a capable worker. Stage B and Stage C a strong worker. Stage D a capable worker.
**Start when:**
- Stage A: `feat/visual-foundation` and `fix/release-cards` (brings `tools/mutants/run.py`) are on `origin/main`.
- Stage B: `feat/a11y-runner`, `feat/inspection-queries`, `feat/inspection-live`, `feat/work-surfaces`, `feat/work-live`, `feat/work-evidence` (unless `31` folded it into Stage B), `feat/setup-config`, `feat/recovery-controls`, `feat/m2.1-specialist-slice`, `feat/m2.2-coordination`, `feat/m2.3-delivery` and `feat/m2.4-recovery` are on `origin/main`, plus `feat/m2.4b-engines` if Codex or OpenCode is enabled for this release.
- Stage C: Stage B is merged, released and verified on the installed app, and the coordinator says so.
- Stage D: prepared whenever the coordinator asks, once before each release tag.

**Can run alongside:**
- Stage A: every other handoff, and all of M2. It adds test tooling only.
- Stages B, C and D: nothing else in this set. They are last, and one at a time.

**Blockers-only review:** not required. Accessibility, release records and removing unreachable UI code are outside the sensitive cases. If Stage B or C has to change anything in `32`'s sensitive controls, stop and report.
**Real-engine runs:** Stage B only, and only for the final composed journey: at most 3 Claude, 1 Codex and 1 OpenCode, for engines enabled in this release, and only if `engine-runs.md` shows room under the cap of 10 (#18). The planner is Claude-only, so a Codex or OpenCode request also spends one Claude line: that is 1 for a Claude specialist request plus 1 for each of those. Claude then reaches exactly 10 across all handoffs, so a retry needs the owner. Scratch repositories only. Stages A, C and D: none.

**The coordinator executes all of these. No agent here does:** merge, tag, GitHub Release, install, restart, or changing the running app (`00-README.md`, #15, #23). This handoff prepares them.

## Outcome

Stage A: the repo has a working axe and Lighthouse gate. Stage B: all six surfaces pass the measured matrix, the composed journey works on the packaged build, and the next shell is the default with classic one parameter away. Stage C: the old shell is gone. Stage D: a correctly versioned artifact and a runbook are ready for the coordinator.

## Requirements

### Stage A: the runner

1. **Dependencies, and only these.** Add `@axe-core/playwright` and `lighthouse` to `apps/web` `devDependencies`, exact versions, with the lockfile. The install must not change other dependency versions. `pnpm audit --prod` in CI ignores dev dependencies (`ci.yml:63`), and the tarball's `npm install --omit=dev` doesn't see them. No other tool. Neither package was installed or tried on this machine when this was written, so the steps below are the design and not a proven recipe. If Lighthouse cannot drive Playwright's chromium here, stop and report; don't swap tools.
2. **Axe, in the screens suite.** `apps/web/test/a11y.screens.playwright.ts`: matches the existing `testMatch`, so no config change. A helper runs `AxeBuilder` on the page and fails on any violation. It also fails if the target surface isn't present or `passes` is empty, so an empty page can't pass. No rule disabled; if one must be, stop and ask.
3. **Lighthouse, as a script.** `apps/web/scripts/lighthouse.mjs`, wired as `test:lighthouse` in `apps/web/package.json`. Takes a base URL and a list of hash routes. Accessibility category only. Threshold 95 per route (UI-OVERHAUL.md "Measurable acceptance"). Non-zero exit on any miss or unreadable result. Uses Playwright's chromium, with `--no-proxy-server` (the fix in `a102313`), and writes JSON reports to `$TMPDIR`, not the repo.
4. **Vacuous-pass guard.** `apps/web/test/fixtures/a11y-broken.html`: a deliberately bad page (no labels, no landmarks, low contrast). A test proves axe reports violations there, and the script exits non-zero against it.
5. **Not in CI, not in `pnpm check`.** Like `test:screens` (`playwright.config.ts`). Document the commands in `docs/agent-workflow/commands.md` and `CONTRIBUTING.md`. Run under the lock in `00-README.md`.
6. Run it on VF0's harness and report the result. Fix nothing outside this PR's files; list failures for Stage B.

### Stage B: the matrix, the journey, the default

1. **Six surfaces (UI-OVERHAUL.md).** Conversation, Work, Needs you, Connections, Setup, Settings, each at 1440, 1024 and 390, light and dark, plus inspector, sheets, palette, drawer, and the states empty, working, blocked, error, completed, resolved, expired. Compare against `ui-overhaul-preview.html` as adjusted by VF0's token changes.
2. **Measured limits.** Text contrast at least 4.5:1, large text 3:1, control and focus 3:1. Body 14px and secondary 12px minimum. Primary controls 40px high. Targets 44px on mobile, 32px for secondary desktop controls. 2px visible focus. Motion at most 160 ms, none nonessential under reduced motion. No horizontal page scroll at 390. No clipped action at 1024.
3. **Axe zero violations and Lighthouse at least 95** on every route, on the real packaged server, not only the harness. Run Lighthouse against a built tree with a scratch `MEC_DATA_DIR` and scratch `HOME`, seeded through real routes with `MEC_FAKE_ENGINE=1`. Axe also runs on the harness states the real server can't reach.
4. **Complete keyboard journey.** Every surface, with focus return. Slash, Cmd/Ctrl+K, Escape chain.
5. **Fix what fails** in the surface's own files. Tell the coordinator before a fix touches behaviour, not presentation.
6. **The composed journey (CHANGE.md "Final assembled outcome").** New `apps/web/test/journey.real.playwright.ts`, run by its own config against the packaged server, with no mocked routes: select a repo, ask once, see the plan, answer a question, inspect a task, approve named cards on the scratch lane with fake `gh`, see the outcome. Then decline, hold, stop, restart and offline paths. Run it on the fake engine first. Then one real pass per the budget above, recorded in `engine-runs.md` and `docs/log/HANDSHAKES.md`, against a scratch repository with a `file://` origin and fake `gh`. The real `mec-sandbox` pass through the cards is the coordinator's (#23): list what remains for it. It's a remote effect, and no agent here makes one.
7. **Traceability.** Repeat `31`'s request-to-PR trace with real attempts and checks, and fill the coverage labels it left open. Any field still "not recorded" gets reported, not hidden.
8. **Flip the default.** `resolveShell` in `apps/web/src/ui-flag.ts`: absent choice gives `next`. `?ui=classic` still works, a stored `classic` still wins, and a store that throws gives `next`. `ui-flag.test.ts` pins the old default, so changing it is an **intended behaviour change**: say so. Add the Settings or palette way back to classic.
9. **Records.** `docs/STATUS.md` and `docs/agent-workflow/architecture-map.md` match composed proof. Leave dated `docs/log/HANDSHAKES.md` credit in place. Update `docs/known-limits.md`, `docs/fault-suite.md` and `docs/CHANGELOG.md`.

### Stage D: release preparation

1. **Three bumps.** `package.json`, `apps/desktop/package.json`, `apps/web/package.json` to the same version. `packages/*` stay at `0.1.0`. `pack-tarball.mjs` reads the desktop version.
2. **Guard the mislabelled-tarball mistake (`393144b`).** `apps/desktop/test/version-sync.test.ts`: the three versions agree. Add one step to the `check` job in `.github/workflows/release.yml` that fails when `GITHUB_REF_NAME` isn't `v` plus the desktop version.
3. **Verify locally, no install.** `pnpm check`, `pnpm build:desktop`, `pnpm --dir apps/web build`, `pnpm pack:internal`. Extract to a scratch directory, `npm install --omit=dev` there, then `node bin/mec.js --version` and a start and healthz with scratch `HOME` and `MEC_DATA_DIR`. This is a smoke run, not an install: nothing touches the owner's install. Note that `pack:internal` must come after the web build.
4. **`docs/CHANGELOG.md`** entry, with no claim that wasn't observed.
5. **The runbook, for the coordinator.** `docs/changes/2026-11-05-<slug>/RELEASE-RUNBOOK.md`, with exact commands, none run by you:
   - confirm CI is green on the commit to tag;
   - tag `v<version>`; the release workflow runs check, tarball, Linux and macOS smoke, then GitHub Release;
   - before installing, keep the prior versioned tarball: `scripts/install.sh` runs `rm -rf` on the install directory's contents before extracting, and it has no rollback;
   - keep a copy of the owner's database taken while stopped, or via `VACUUM INTO`, and never delete it. A reinstall doesn't undo data writes (CHANGE.md "Rollout");
   - install, restart, hard refresh, repeat the journey on the installed version;
   - rollback: reinstall the prior tarball, and in Stage B's release use `?ui=classic` first. A newer schema blocks an older binary, but this release has no migration;
   - no npm publication, no vendor or account change (#15).
