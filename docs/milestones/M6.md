# M6 — Workspaces and checks

**Backlog tickets:** 10 (repository registration, bootstrap, submodules), 11 (task workspace
lifecycle, ports, check capture).

## What it does

- **One clone per repository, one worktree per attempt** (PDF §6, §14). The runner keeps a bare
  clone in `~/mec/repos/<name>-<hash>.git` and adds `~/mec/work/<attempt>` on branch
  `mec/<delivery8>/<task>/a<n>` at the **pinned base**. The first attempt of a delivery resolves
  `baseRef` and reports the SHA; control pins it on the delivery, and every later attempt starts
  from that exact commit even if `main` moves. Submodules are initialised recursively and their
  SHAs recorded; unavailable content fails preparation with a clear message.
- **Bootstrap, then the agent, then verification.** The repository validation profile's
  bootstrap commands run before the agent starts (a failure is `bootstrap_failed`, an environment
  problem, not the agent's). When the agent stops, the runner commits anything uncommitted, records
  the diff against the base (`workspace.diff`: files, insertions, deletions, patch artifact), and
  runs the task's acceptance checks against that exact SHA.
- **Check results.** Each check is an argv command with a timeout, run in its own process group.
  The outcome is `passed` (exit 0), `failed` (it ran and reported failure) or `error` (it could not
  start or timed out) — the distinction PDF §15 asks for. Exit code, duration, tested SHA, a log
  tail and the full log artifact are stored in `check_results`.
- **Artifacts.** Runners upload logs and patches with their device token, only for attempts they
  own; files live under `ARTIFACTS_DIR`, rows hold the reference and SHA-256. People download by id
  (`nosniff`, no active content) — never by path.
- **Isolation of credentials and ports.** Agents and checks get a minimal environment
  (`PATH`, `HOME`, `CI`, `MEC_ATTEMPT_ID`, a unique `PORT` range per attempt). A fine-grained token
  (`MEC_GIT_TOKEN`) is used only by the runner's own git calls through an askpass helper — never on
  a command line and never in the agent's environment. With a token, branches whose checks passed
  are pushed for review visibility.
- **Workbench.** The task view shows branch, base and head SHAs, the diff summary with the patch,
  and each check with its log.

## How to read it

| Path | Purpose |
| --- | --- |
| `packages/git/src/` | argv-only git, clone cache with per-repo locking, worktrees, commits, diffs, push |
| `apps/runner/src/workspace.ts` | Prepare / finalize / push, askpass helper |
| `apps/runner/src/checks.ts` | Supervised check execution and outcome classification |
| `apps/runner/src/runner.ts` (`run`, `verify`) | The attempt loop end to end |
| `apps/control/migrations/0005_workspaces_checks.sql` | `artifacts`, `check_results`, `attempts.diff` |
| `apps/control/src/features/runners/ingest.ts` (`projectEvidence`) | Pins base, records diff and check results |
| `apps/control/src/features/artifacts/routes.ts` | Upload (runner) and download (people) |
| `packages/testkit/src/repo.ts` | Local fixture repositories used as `file://` remotes |

## How to demo

`pnpm vitest run apps/control/test/workspace-e2e.test.ts packages/git` — a fake agent edits files
in a worktree on the pinned base; the diff, the passing check against the head SHA, the log and
patch artifacts and the pushed branch are all verified; a failing check and an unstartable check
are told apart; a second attempt stays on the pinned base after `main` moves; a failing bootstrap
fails the attempt clearly.
