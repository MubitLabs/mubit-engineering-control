## Outcome

On the next shell (`?ui=next`) the owner sees Conversation, Work and Needs you with real data, and can search. They can follow one request from message to plan, tasks, attempts, checks, diff and PR. They can answer a question or settle a named approval. Specialist activity is inspect-only. The classic shell stays the default.

## Requirements

1. **Conversation (§18.1, §12, UI-OVERHAUL.md).** Render one repository's messages with `UserMessage`, `AgentMessage`, `ActivityNote` and `DeliveryPlan` from `next/Conversation.tsx`. The request title leads. Acknowledgement, plan and quiet progress only; routine tool activity stays out (§18.1). Follow §12.7 wording: no paths, hashes or test counts in chat text. Composer intent and drafts stay with M1.3. "Discuss this work" calls M1.3's intent setter and nothing else. "Inspect" opens evidence and never a specialist chat.
2. **Work (§18.3).** A delivery list grouped by stage: open, queued, working, waiting, held, ended. Each row has title, repository, stage label, reason and next step. No per-row detail fetch (`Work.tsx:97-114` does that today). Ended rows show their outcome. A selected delivery expands tasks with dependencies and delegation shown separately: dependencies come from `dependsOn`, delegation from `delegation`, and neither is inferred from the other. Fix the classic mistakes rather than port them: held and dropped mapped to Working, every blocked item called "Needs your approval", quota inferred from parked (`Work.tsx:22-26,53-54`).
3. **Inspector (UI-OVERHAUL.md "Inspector").** Map `TaskDetail` to `InspectorScope` and approval evidence to `kind: 'approval'`.
   - Tabs are Overview, Checks, Activity, Diff.
   - Show requested tier and actual model separately.
   - Checks list results only for the scope's exact head. An in-progress task shows "not run yet" and never inherits a card's checks.
   - `coverage` false renders "Not recorded yet", never an empty success.
   - Internal ids stay in folded details (§18).
   - The originating row stays selected.
   - This is the live proof of prototype defects 7 to 13 (`wave0-design.md`), which VF0 left to this PR.
4. **Needs you (§18.2, §13, #11, UI-OVERHAUL.md).** Questions and cards from `/api/inspect/needs`.
   - Use `Approval` and `Question` from `next/Decision.tsx`. Two-step arming already lives there; don't rebuild it.
   - Card evidence comes from `GET /api/inbox/:id/detail` and settles through `api.resolve`. Use `describeApproval` from `apps/web/src/release-cards.ts` for the outcome, so a hold keeps the card open and names why. Approved is not executed.
   - A question answers through `POST /api/questions/:id/answer` with `{answer}`. A 409 shows that it was already answered.
   - Keep resolved and expired items visible. Amber appears only on open items.
   - A healthy empty state takes no space and says nothing false: a read failure is never "nothing waiting".
   - `needsCount` passed to the sidebar comes from the same list, and `null` while unknown.
5. **Repository scope (#10, research-user-journey).** Work and Needs offer All repositories, read-only until an explicitly repo-labelled action is chosen. Every action uses the item's own id and repository, never the selected filter. Unassigned legacy work is shown and has no actions.
6. **Hold, lift, stop (§10, §12.5, #20).** Work offers the M1.4 routes. Lift is explicit and only ever owner-driven. Stop uses the two-step pattern, because §18 says destructive actions confirm, and it names what stops. Don't offer Pause: `32` owns it (#22).
7. **Search (§18).** A `SearchSheet` built on `Sheet`, opened from one new toolbar button and one palette command. Results from `/api/inspect/search`, labelled by kind and repository. Choosing a result navigates and selects; it never changes composer intent or send target. The palette stays a command filter (`CommandPalette.tsx`).
8. **Freshness (CHANGE.md design item 6).** Keep content on failure, show when it was last read, offer Retry. One merged SSE connection only. On `error`, close the `EventSource` and reopen with your own cursor vector, because native reconnect replays the original `after`. On `event: reset`, take a new snapshot and say so. Stale evidence is labelled and never silently current.
9. **Finite states (§18, M1.1).** Every read ends in ready, empty or failed. No fixture fallback (`no-fixtures-in-src.test.ts`, M1.1). Don't import `components/LoadState.tsx`: it depends on classic `Btn`, and classic is removed in `33`. Use `next/states.tsx`.
10. **The walls stay.** `next/*` stays props-only, and `next-boundary.test.ts` stays unchanged. Live reads and effects sit in `apps/web/src/live/`, the layer `12-m1.3-repo-workspace.md` creates. `12` also renders a basic Conversation and Work there; Stage B replaces those with these surfaces. No fixture, `api.ts` or `fetch` inside `src/next`.
11. **The flag stays.** No change to `ui-flag.ts` defaults. Classic behaviour and baselines are untouched.
12. **Measures.** UI-OVERHAUL.md "Measurable acceptance" applies to these three surfaces and their inspector sheet at 1440, 1024 and 390 in both themes.

## How to build before M3.1 lands

The fixtures are typed against the wire, pass through the real decoder and view-model code, and live only in `apps/web/test`.

1. Copy the wire types from `30-m3.1-canonical-inspection.md` ("The wire shape") into `apps/web/src/next/inspection-wire.ts`. Types only.
2. `apps/web/src/inspection-decode.ts`: pure decoders from `unknown` to those types, throwing M1.1's `DecodeError` (`api-decode.ts`). A payload that doesn't fit never renders.
3. `apps/web/src/next/work-model.ts`: pure functions from wire types to component props, with no React. All stage grouping, count and scope logic goes here, so vitest can test it. There is no jsdom and no new dependency.
4. `apps/web/test/fixtures/inspection-fixtures.ts`: raw payload objects, checked with `satisfies` against the wire types. Cover every state: empty, working, blocked, failed, held, quota, completed, resolved, expired, partial coverage, and a read error. Put the string `SAMPLE-ONLY` in each.
5. `apps/web/test/fixtures/work-harness.html` and `work-harness.tsx`: a new harness, so `next-harness.tsx` stays unshared. It runs fixture → decoder → `work-model` → components. VF0's tsconfig already includes `test/fixtures`.
6. `apps/web/test/work.screens.playwright.ts` drives it. The name matches the existing `testMatch`, so no config change.
7. Keep fixtures out of the product, three ways:
   - The harness is served only by the Vite dev server. The only production entry is `index.html`.
   - `next-boundary.test.ts` already scans every file in `test/fixtures` and refuses its sentences in `src/next`.
   - Add one `it` to `apps/web/test/shell-split.test.ts`, which already runs a real build in `pnpm check`: `dist/assets contains no SAMPLE-ONLY`.
8. Stage B swaps the data source only: live fetches go through the same decoder and the same `work-model`. Then `apps/web/test/inspection-contract.test.ts` proves the fixtures' shape against a real server. Copy the pattern of `web-contract.test.ts` (M1.1), but use `SqliteStore`, because `InspectionReads` needs SQL and `MemoryRepositories` has none.

If M3.1 changes a field, the contract test fails and the fixture changes with it. That is the point of the test.

## Stage C: the evidence only `30` Stage 2 serves

1. Activity tab: pages of `ActivityItem` from `GET /api/inspect/attempts/:id/activity`, through a decoder and `work-model`. Read the shape as merged. Inspect-only, never "currently running" from a `tool_call`.
2. Artifacts: open a check's or report's `artifactRef` through `GET /api/inspect/artifacts`, as plain text. Binary shows metadata only.
3. Events: `/api/events?compact=1`, invalidating the affected read. On `event: reset`, take a new snapshot and say so.
4. Tests, red first: `apps/web/test/work-model.test.ts` `activity has no running state from a tool call`; `apps/web/test/sse-resume.test.ts` `compact frame invalidates one read`. Mutants in `tools/mutants/m3.2-evidence.json`: `tool call implies running`, `compact frame ignored`.
5. Verifier: on the scratch server, a seeded attempt shows redacted activity and an artifact, and a forced `reset` gives one snapshot with no gap or duplicate against SQLite.
