## Outcome

With `MEC_REAL_RUNNER=1`, a real launch effect starts one Claude specialist on a registered repo. The attempt runs in its own worktree under a real journal, reports through scoped tools, and ends with a commit, a head SHA and repo check results on that exact SHA. With the flag off, nothing changes from M1.4b: work blocks with a stated reason and no process starts. Nobody dispatches a worker by hand. Remote effects remain impossible from a worker.

## Requirements

1. **Flag.** `MEC_REAL_RUNNER=1`, read in `startServer`, default off (CHANGE "Rollout, flags"). `MEC_FAKE_ENGINE=1` keeps priority and its path stays as it is. The flag grants no authority: mandate, hold and repo checks still run on every launch.
2. **Seam.** Implement the contracts `Runtime` interface (`packages/contracts/src/runtime.ts`) in `packages/runtime/src/attempt-runner.ts`, with the adapter and git operations injected. `@mec/engines` depends on `@mec/runtime`, so runtime importing engines is a cycle. Implement `CoreForEngines` on the store in `apps/desktop/src/core-facts.ts`; only testkit's memory version exists. `deliver` throws a named not-wired error until M2.2; `replay` likewise until M2.4. Registry of engines this build may launch: Claude only.
3. **Launch handler (§17).** `launchHandler` (`composition.ts:366`) keeps `launchAuthority` from `10` first, and its `drop` and `defer` results. With the flag on, replace the `no_runner` block from `11`; with it off, that block stays. Return after the engine has started; a separate monitor owns the attempt. The effects queue counts in-flight jobs against the kind's concurrency (2 here) and `drain` awaits them (`fix/effects-double-run`), so a handler that awaits the whole attempt caps attempts at 2 and blocks shutdown.
4. **Launch order (§8, §14, §5.12).** Load attempt, task, work, repo and slot, and refuse unless all agree. Then cache, pin base, worktree, `.mec/` files, bootstrap, model, bundle, token, env, engine start. `AttemptBrief.parse` the brief. Never persist `brief.tools.token` (`brief.ts`, §17).
   - Worktree `<dataDir>/work/<attempt>`, branch `mec/<work-item8>/<task>/a<n>`. Repos under `<dataDir>/repos`. A registered local path becomes `file://` for `RepoCache` (which accepts only `https://` and `file://`).
   - Model: `resolveModel`. A refusal fails with a reason and spends nothing.
   - Bundle: assemble for role and engine, pin `bundle_revision` (§16.1). `ClaudeAdapter.launch` sends only `brief.objective`, so put the bundle, the verbatim original request (§10) and the task objective in it, as `brain.ts` does for the planner.
   - Env: slot layer is `slot.env`, never a synthesised `CLAUDE_CONFIG_DIR`: a linked slot runs with the variable unset (`homes.ts`). Attempt layer per §5.12.
   - Call `tools.bumpGeneration(attemptId)` at every launch. It counts from 0 and generations start at 1 (`service.ts:753`), and `isStale` is `ctx.generation < current`.
   - Bootstrap runs the repo's `bootstrap` strings as argv on the worktree. Registration refuses shell metacharacters (`server.ts` `argvArrayOf`). Always pass `env` to `runCheck`: with it undefined, `spawn` inherits the host environment including keys.
5. **Defects that block the slice.** Each has a test below.
   - a. **The engine runs its own shim.** Adapter argv[0] is `claude` (`argv.ts`) and `buildAgentEnv` puts the shim dir first on `PATH`. Probe on this machine: `spawn('claude', …, {env:{PATH: shimDir+…}})` ran the shim, exit 127. `h1.real.test.ts` never sets `shimPath`, so this was never exercised. Resolve the absolute binary from the user's `PATH` before building env and pass it through a new `ClaudeAdapterDeps` field (§26 compliance row).
   - b. **`RepoCache.ensure` deletes task branches.** Its second call runs `git fetch --prune --force origin '+refs/heads/*:refs/heads/*'` in the bare cache (`repos.ts`). Probe: `mec/*` branches vanished, including one checked out in a live worktree, exit 0. Any second attempt on a repo would do this. Fetch so `mec/*` survives, for example into `refs/remotes/origin/*`, and take the pinned base from there.
   - c. **No process-group ownership.** `defaultSpawn` isn't detached and `adapter.stop` signals only the child; `Supervisor.spawn` uses `stdio: 'ignore'`, so it can't carry stdout. Inject a `SpawnFn` from runtime: detached, piped, registered with `Supervisor`. Stop is `Supervisor.stop` (§8.1).
   - d. **Events arrive only at exit.** `ClaudeAdapter.events` buffers all stdout, then parses. A crash loses everything and `running` can't be observed. Add a stateful line parser in the shape of `createCodexEventParser`. Keep `parseClaudeStream` as its wrapper so fixtures stay valid. The exit event still needs the real exit code.
   - e. **Sandbox deny list misses the database.** `defaultDenyRead` lists `~/.mec/db`; the file is `<dataDir>/mec.db` (`composition.ts:74`), and the list hardcodes `~/.mec`, so a scratch data dir gets no denial at all. Take `dataDir`. Enumerate `mec.db*`, `health.json`, `policy.yaml`, `prompts`, `journal`, `engines`, and add `~/.claude`, `~/.codex`. Don't deny the data dir whole: the worktree sits under it and its `.git` file points into `repos/`. §8.4 also names `sandbox.credentials.files`, which `AttemptSettings` lacks. I couldn't verify that key against 2.1.317; check `docs/engines.md`, and if it's unproven say so instead of adding a guess.
   - f. **A specialist can commit its bearer token.** `.mec/mcp.json` sits in the worktree. `commitAll`'s exclusion doesn't cover the agent's own `git add`. Add `.mec/` to the common `info/exclude` (probe: `git rev-parse --git-path info/exclude` resolves to the bare cache and hides `.mec/` in the worktree). Also fail the attempt if the head's diff from base touches `.mec/`, which catches `git add -f`.
   - g. **Boot order.** The queue starts at `composition.ts:113-118`, before `tools.start()` at `:145`. Start the queue after tools are up. Keep the `resumeRunning()` line from `fix/effects-double-run` before the first pass.
   - h. **Scratch servers read real prompts.** `11` passes `keystoreRoot: opts.dataDir` (its requirement 16). Confirm it landed before any real run with the real `HOME`.
6. **Permission boundary (§6, §13, §26 "Platform-tool fencing").** Replace `onCall` (`composition.ts:141`) and, for the specialist path, `DENY_BRIDGE`.
   - `report`, `read`, `confirm` work. `ask_user`, `handback`, `request_confirmation` return a named error until M2.2, never success. A `meta_agent` token is refused here; the brain has its own server.
   - `read` covers only the token's own task, attempt, delivered messages and prompt revision. Every other id is refused.
   - `confirm` returns Claude's `{behavior, updatedInput?}` shape. Allow edit and write inside the worktree and attempt temp dir; allow Bash under the required sandbox; deny anything matching `ALWAYS_CONFIRM` (`git push`, `gh pr`, branch delete, force); deny everything else with a reason. Record every ask with `permissionRequested`. Cards are M2.2's: §9's card path is narrowed to deny here.
   - Isolation: `sandbox: 'required'`, `permission_mode: 'bridge'`, `read_only` from the role registry, `repo_trusted` from the repo doc. Repo docs carry no isolation profile yet; use a constant. Decision #22's Repositories home is M3.3.
   - Write no credential helper into the attempt gitconfig (it's optional in `writeAttemptGitconfig`). Network allowlist: the engine's own domains plus nothing else. The repo doc has no registry-domains field (§14), so a bootstrap needing the network fails; record it as a limit. Shims are not a boundary (`shims.ts` header).
7. **Journal and facts (§8.6).** Order: `redactEvent` with fingerprints and the attempt token as exact → `AttemptJournal.append` (fsync) → one store transaction for facts, state and event → `journal.ack`. Keep the spec path `<dataDir>/journal/<attempt>/`. `append` refuses a non-increasing seq and the adapter restarts seq at 1, so assign `lastSeq()+1` in the runner and keep generation on the event.
8. **State.** Move attempts and tasks only through `ATTEMPT_MACHINE` and `TASK_MACHINE`: `queued→running` on `session_started`, `running→work_complete` on exit, task `attempt_started`, `work_complete`, `attempt_failed`. Parking via `parkFromEvents` at exit is enough here. Live parking is M2.4.
9. **After exit (§10, §15).** `commitAll` any leftover tree, read `headSha`, run the `.mec/` guard, then run the repo's `checks` on that head. Store each as `check/<attemptId>/<name>` in `store.engines`: name, status, exit code, duration, redacted log tail, SHA. All passed → `succeeded`; any failed or error → `checks_failed`. No checks registered: stay `work_complete` and say why. An exit 0 never yields `succeeded` alone.
10. **Reports.** Parse with contract `Report`, store `report/<attemptId>/<n>`, append an event. A `head_sha` that differs from the real head is recorded, never trusted. No wake yet.
11. **Bounds and stop.** Turns from the task budget, else the role's `budgetTurns`. Enforce wall clock with a timer into `Supervisor.stop`, ending `interrupted`. `stopWork` from `10` only appends `attempt.interrupt_requested` for running attempts and leaves the kill to this PR: act on it through `Supervisor.stop`, then `interrupt_confirmed`. The same applies to the planner's `stop_agent` (`#persistExtras`), which sets `interrupted` directly today. In the bounded `close` from `11`, stop owned groups before `tools.stop()`.
12. **Failure.** §17: passing failures retry per the launch row; any other failure and a failed bootstrap fail the attempt. Route all of them through one function so the open question below changes one place. A launch of a non-registry engine fails explicitly with no spend.
13. **Docs.** Reconcile `docs/STATUS.md` and `docs/agent-workflow/architecture-map.md` composition claims. Add the flag to `docs/reference.md`. Real-run result goes to `docs/log/HANDSHAKES.md`.

No contracts change and no SQL migration is expected. If you find you need either, stop and report.

## Open questions

1. **§14 pinned base timing.** "Always on a pinned base", not when, and repo docs have no default branch. Open because M1.2 pins profile and policy at admission but not a SHA. Recommend pinning the SHA at first dispatch: the cached clone's `HEAD` tip after `ensure`, stored on the work item once and reused by every later task.
2. **§17 "fails the attempt", no failed state.** `ATTEMPT_STATES` has none. `ATTEMPT_MACHINE`'s only exits from `queued` are `agent_started` and the `interrupt_confirmed` row `10` adds. `11` asks the same question for its `no_runner` block. The state list is in `packages/domain/src/states.ts`, not frozen contracts: `packages/contracts/src` has no attempt-state enum, so no contracts change is needed. Spec §10's table does change. Recommend a terminal `failed` from `queued` and `running`, plus one §10 line. Rejected: `checks_failed` (scorecards would report a launch failure as a check failure) and `interrupted` (it's resumable). Until answered: follow `11`: leave the attempt `queued`, block the work with the reason, let the effect row end `failed`.
3. **What is one "run" (#18).** A composed request starts two Claude processes, planner and specialist. Recommend one bounded request is one run per engine involved, one line in `engine-runs.md`. If the owner counts processes, 3 buys one request and a half: stop and tell the coordinator.
4. **§8.4 and checks.** The sandbox covers the engine's shell. Repo checks then run agent-written code on the host with no sandbox. Spec is silent. Recommend accepting this for scratch repos with a scrubbed env and no tools token, and deciding before the flag goes on for a real repo.
5. **§8.3 commit identity "from policy".** `PolicyDoc` has no such field. Recommend the registered repo's own `user.name` and `user.email`, falling back to refusing the attempt.
6. **§11 wall-clock default.** Tasks may omit budgets. §8.5's 30 minutes is about background work. The role default gives turns only. Recommend 30 minutes until policy carries a value.
