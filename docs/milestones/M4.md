# M4 — Runner and protocol

**Backlog tickets:** 03 (enrolment, device identity, heartbeat), 04 (supervisor, journal,
reconnect), testkit.

## What it does

A runner is a persistent daemon owned by one employee (PDF §6). It is not an LLM: it prepares
workspaces, supervises agent processes, journals their events before forwarding them, and executes
control commands at most once.

- **Enrolment.** An admin creates a single-use, one-hour invitation (Fleet page, or
  `node apps/control/dist/admin.js invite --owner <login> --label <text>` on the host). The runner
  exchanges it for a device token (`mec-runner enrol …`), which is written to
  `~/.config/mec/runner.env` (0600). Control stores only the token's SHA-256.
- **Connection.** The runner dials out over WebSocket (`/runner/ws`, bearer device token), sends
  `hello` with OS, arch, capacity, agent probes and the attempts it holds, and receives `welcome`
  with the highest persisted sequence per attempt. Heartbeats every 10 s renew leases for live
  attempts of the current generation; 45 s of silence closes the socket.
- **Events.** Each event is appended to `~/mec/journal/<attempt>/events.jsonl` and fsynced first.
  Control deduplicates on (runner, eventId), rejects a sequence that goes backwards, flags gaps,
  stores events from a fenced generation as evidence without letting them change state, and
  acknowledges only after commit. The runner drops acknowledged events from its replay buffer and
  resends the rest after every reconnect, strictly in sequence order.
- **Commands.** Starting an attempt is one transaction: attempt row, lease (generation 1, 60 s),
  unique active slot per task, task `ready → active`, and a `start` command in the outbox. The
  dispatcher sends queued commands to connected runners and retries unacknowledged ones; the runner
  records processed commandIds, so a redelivered command is reported `duplicate`, not re-run.
- **Supervision.** Processes start from argv arrays in their own process group; stop sends SIGTERM
  to the group, escalates to SIGKILL, and waits until the whole group is gone. Ownership is
  (attemptId, generation). After a runner restart nothing from the old process survives (systemd
  stops the cgroup), so each active attempt is journalled as `attempt.interrupted`.
- **Fake agent.** A real child process speaking JSON lines (say, sleep, write, tool, ask,
  requestApproval, fail, exit quota/auth) with checkpoints, so resume works like a vendor CLI.
- **UI.** Fleet page (runners, health, agents, capacity, drain, revoke, invitations) and a task
  workbench with the attempt transcript, interrupt and cancel.

| Path | Purpose |
| --- | --- |
| `packages/contracts/src/runner-protocol.ts` | Envelope, event types, commands, WebSocket messages |
| `apps/control/migrations/0003_runners_attempts.sql` | Invites, runners, attempts, active-slot index |
| `apps/control/src/features/runners/gateway.ts` | WebSocket endpoint: auth, hello, ordered handling, acks |

| `apps/runner/src/runner.ts` | Command handling, attempt loop, ordered flush |
| `apps/runner/src/journal.ts` | Durable journal with ack cursor |
| `apps/runner/src/supervisor.ts` | Process groups and confirmed termination |
| `packages/agents/src/adapter.ts` | Adapter contract and capability flags (for Claude, Codex, OpenCode) |
| `packages/testkit/src/index.ts` | Scriptable fake runner for protocol tests |

## How to demo

On the droplet the runner is `mec-runner.service` running as `max`:

```bash
ssh openclaw systemctl status mec-runner
ssh openclaw journalctl -u mec-runner -f
```

Tests (`apps/control/test/runner-*.test.ts`, `apps/runner/test/`): single-use invitations,
token-only WebSocket, online/offline, revocation; idempotent command redelivery and duplicate
dispatch; offline queueing; lifecycle to `awaiting_review`; duplicate events stored once;
sequence regressions and gaps; fenced generations; cross-runner refusal; lease renewal; and with
the real runner + fake agent: success, a dropped connection mid-attempt, a runner restart
mid-attempt (no lost or duplicated events, contiguous sequences), interrupt, and agent failure.
