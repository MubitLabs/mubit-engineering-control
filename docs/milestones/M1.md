# M1 — Domain and policy (pure rules, no I/O)

**Backlog tickets:** 13 (approval integrity), 14 (task-graph validation), 16 (lease rules).

## What it does

Every rule that decides *whether something may happen* lives here as plain functions, so the
control service, scheduler and UI can all call the same code and the tests need no database.

| Rule | File | Spec |
| --- | --- | --- |
| Delivery, plan revision, task, attempt and approval lifecycles | `packages/domain/src/states.ts` | PDF §11, §13 |
| Task-graph validation (cycles, missing deps, unknown requirements/checks/profiles, budgets) and conflict signals (path overlap, lockfile/migration/generated/config hotspots) | `packages/domain/src/task-graph.ts` | PDF §8 |
| Approval admissibility: pending, not expired, listed decider, binding hash unchanged | `packages/domain/src/approval.ts` | PDF §13 |
| Lease fencing by runner + generation, renewal, generation bump, sequence checks | `packages/domain/src/lease.ts` | PDF §11, §25 |
| Blocker reasons and dependency satisfaction per base policy | `packages/domain/src/blockers.ts` | PDF §8, §11 |
| Permission table: observe / prompt / use_profile / resolve_approval / approve_plan / merge … | `packages/policy/src/index.ts` | PDF §5 |
| Task specification schema | `packages/contracts/src/task-spec.ts` | PDF §8 |

## How to read it

Start with `states.ts`. Each machine is an explicit table; anything not in the table is rejected.
The reviewed tables are pinned as snapshots in
`packages/domain/test/__snapshots__/states.test.ts.snap`, so any change to a lifecycle shows up in
code review as a diff of readable lines like `running --lease_expired--> stalled`.

Design choices worth knowing:

- `work_complete` only means the agent stopped. Checks move an attempt to `succeeded` or
  `checks_failed`; only review moves the *task* to `accepted`.
- Lease expiry moves an attempt to `stalled`, not to a replacement. A replacement can only start
  after the runner reconciles (`runner_reconciled_stopped`), see PDF §11.
- Telemetry from an expired lease is still journalled; authoritative actions (results, pushes,
  task state) need a live lease and the current generation.
- A code dependency (`basePolicy: integration`) is satisfied only by `integrated`; an interface
  dependency (`contract`) by `accepted`.
- Admins never inherit approval authority; deciders are bound per approval.
